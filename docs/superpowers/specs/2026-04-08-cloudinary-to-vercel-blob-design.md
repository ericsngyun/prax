# Cloudinary to Vercel Blob Migration — Design Spec

## Goal

Replace Cloudinary with Vercel Blob as the single asset hosting platform for all images (~50) and videos (3). Eliminate double-optimization (Cloudinary transforms + Next.js Image proxy) by serving raw originals from Blob and letting Next.js handle all image optimization.

## Architecture

**Image pipeline (after):**
Browser → Vercel Blob CDN (raw file) → Next.js Image Optimization (AVIF/WebP, responsive sizing, edge caching) → User

**Video pipeline (after):**
Browser → Vercel Blob CDN (direct serve, no proxy) → User

**Key constraint:** Vercel Blob stores raw/original files. Next.js `<Image>` handles all optimization (format conversion, responsive sizing, quality). Videos bypass the image proxy entirely.

## Deployment

- Hosting: Vercel (already deployed)
- Storage: Vercel Blob (same platform)
- Image optimization: Next.js built-in (already configured in `next.config.ts`)

## File Changes

### New files

- `scripts/migrate-to-blob.ts` — One-time migration script. Downloads each asset from its current Cloudinary URL (stripping transforms to get the original), uploads to Vercel Blob via `@vercel/blob`, outputs a JSON map of `{ assetKey: blobUrl }`.
- `lib/assets.ts` — Replaces `lib/cloudinary.ts`. A flat map of asset keys to Vercel Blob URLs. No transform logic. Exports the same asset keys (e.g., `assets.teamJack`, `assets.portfolio01`, `assets.heroVideo`).

### Modified files

- `next.config.ts` — Replace `remotePatterns` from `res.cloudinary.com` to `*.public.blob.vercel-storage.com`.
- `lib/blurPlaceholder.ts` — Remove `getCloudinaryBlurUrl()` function (generates Cloudinary-specific blur transform URLs). Keep the `blurPlaceholders` object and `getColorBlurPlaceholder`/`getGradientBlurPlaceholder`/`getShimmerPlaceholder` (all self-contained base64 SVGs, not Cloudinary-dependent).
- All files importing from `@/lib/cloudinary` — Update import path to `@/lib/assets`. The asset keys stay the same to minimize churn. Affected files:
  - `app/page.tsx`
  - `app/about/page.tsx`
  - `app/academy/page.tsx`
  - `app/team/page.tsx` (also migrate inline Cloudinary URLs to the asset map)
  - `components/sections/HeroSection.tsx`
  - `components/sections/FounderSection.tsx`
  - `components/sections/PortfolioSection.tsx`
  - `components/sections/InnerPageHero.tsx`
  - `components/sections/ProcessGallerySection.tsx`
  - `components/sections/BeforeAfterGallery.tsx`
  - `components/layout/Header.tsx`
  - `components/sections/Footer.tsx`
  - Any other file importing `cloudinaryAssets`

### Deleted files

- `lib/cloudinary.ts` — Fully replaced by `lib/assets.ts`.
- `scripts/upload-to-cloudinary.js` — No longer needed.

### Unchanged

- All `<Image>` component usage (just different `src` URLs)
- `blurPlaceholders` object (base64 SVGs, self-contained)
- `next.config.ts` image formats, sizes, cache TTL settings
- No component API changes

## Migration Script (`scripts/migrate-to-blob.ts`)

### Behavior

1. Reads the current `cloudinaryAssets` mapping to get all asset URLs
2. For each asset:
   - Fetches the file from Cloudinary (using `f_auto,q_100` for images to get best quality original, or the raw video URL)
   - Uploads to Vercel Blob via `@vercel/blob` `put()` with `access: 'public'`
   - Records the returned Blob URL
3. Writes the complete mapping as a TypeScript file (`lib/assets.ts`)
4. Validates: checks that every asset key has a non-empty Blob URL
5. Fails loudly if any upload fails (no partial migrations)

### Requirements

- `BLOB_READ_WRITE_TOKEN` environment variable (from Vercel project settings)
- `@vercel/blob` npm package (dev dependency)
- Network access to both Cloudinary and Vercel Blob

### Output

Generates `lib/assets.ts`:

```typescript
// Auto-generated by scripts/migrate-to-blob.ts
// Vercel Blob URLs for all static assets

export const assets = {
  // Brand
  logo: 'https://abc123.public.blob.vercel-storage.com/prax-logo.png',
  logoX: 'https://abc123.public.blob.vercel-storage.com/prax-logo-x.png',
  // ... all other assets
  
  // Videos
  heroVideo: 'https://abc123.public.blob.vercel-storage.com/hero-bg.mp4',
  academyVideo: 'https://abc123.public.blob.vercel-storage.com/academy-prax.mp4',
  aboutVideo: 'https://abc123.public.blob.vercel-storage.com/about-prax.mp4',
} as const;

// Re-export for backward compatibility during migration
export const cloudinaryAssets = assets;
```

The `cloudinaryAssets` re-export allows a two-step migration: first run the script, then update imports in a separate commit.

## `lib/assets.ts` Design

A flat, typed, read-only map. No URL builder functions, no transform logic. Next.js `<Image>` handles all optimization.

```typescript
export const assets = {
  logo: '...',
  teamJack: '...',
  portfolio01: '...',
  heroVideo: '...',
  // etc.
} as const;
```

Consumers use it exactly like they use `cloudinaryAssets` today:
```tsx
<Image src={assets.teamJack} alt="Jack" ... />
```

## `next.config.ts` Changes

```typescript
remotePatterns: [
  {
    protocol: 'https',
    hostname: '*.public.blob.vercel-storage.com',
  },
],
```

Replace the existing `res.cloudinary.com` pattern. Keep all other image config (formats, sizes, cache TTL).

## Video Handling

Videos serve directly from Vercel Blob URLs. The `VideoBackground.tsx` component already uses a `<video>` element with `<source>` — it just gets a different `src` URL. No changes to the component itself.

Videos are NOT processed by Next.js Image (they can't be). They're served as-is from Blob's CDN with standard HTTP caching.

## Error Handling

- Vercel Blob down → Next.js Image shows existing `blurDataURL` placeholder (base64 SVGs, self-contained)
- Migration script failure → exits with error, no partial state written
- Missing asset key → TypeScript compilation error (`as const` makes keys strict)

## Rollback Plan

If issues arise after migration:
1. `lib/cloudinary.ts` is still in git history
2. `next.config.ts` remote pattern can be reverted
3. Cloudinary assets remain accessible (we're not deleting the Cloudinary account)

## Out of Scope

- Cloudinary account deletion (keep as backup until verified)
- Dynamic image uploads (site uses only static assets)
- Video transcoding/optimization (acceptable as-is)
- Image format or quality tuning (already configured in `next.config.ts`)
